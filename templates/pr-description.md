# PR 描述模板 — 合入主干前必填（三空未填齐禁止 merge）

```markdown
## 本次改动
<一句话：类型(范围) + 核心变更>

## 为什么
<决策理由；推翻了哪些备选方案，为何选这条>

## 验证
- [ ] <命令/测试 1> → <实际输出摘要>
- [ ] <命令/测试 2> → <实际输出摘要>
（每项贴真实运行结果，禁止"应该没问题"）

## 风险与回滚
<已知风险；出问题如何回滚（revert hash / 关 feature flag）>
```

纪律：
- 合并顺序尊重依赖：被依赖的分支先合。
- 共享分支冲突逐 hunk 解决，解决后跑测试再合。
- 合入后删除本地与远端分支。
