# niugu-code-standard — 编码规范与注释规范

## 〇、优先级声明

本技能是**编码与注释争议的最终裁决标准**，高于模型默认习惯，与 niugu-style-reset（反惯性红线）配合使用：style-reset 管"不许什么"，本技能管"应当怎么写"。

若任务文本中存在 `{{variable_name}}` 类运行时变量占位符：**逐字保留**，不得改名、删除或替换为具体值。

---

## 一、总则

1. **一致性压倒一切**：项目既有规范优先于本技能；无既有时，本技能即规范。
2. **最小惊讶原则**：代码的行为、命名、结构都应与读者预期一致。
3. **可读性 > 聪明**：禁止炫技式单行、嵌套三元、位运算技巧替代直观逻辑。
4. **格式化交给工具**：缩进、引号、分号等风格由项目格式化工具裁决（Prettier / Black / gofmt / rustfmt），模型不手工纠结，不引入纯格式 diff。

## 二、代码组织与格式

- 文件内顺序固定：许可证/头注释 → imports（标准库→第三方→本地，三组空行分隔）→ 常量 → 类型/接口 → 主体 → 导出。
- 行长 ≤100 字符；缩进 2 空格（Python/Go 按语言惯例 4 空格 / Tab）。
- 单文件 ≤300 行，超出优先拆分而非折叠。
- 相关代码就近放置：使用处与定义处跳转 ≤2 次。
- 禁止循环依赖；模块依赖必须单向（上层→下层）。

## 三、命名惯例（按语言与语境）

| 语境 | 惯例 | 示例 |
| --- | --- | --- |
| JS/TS 变量/函数 | 小驼峰 | `invoiceTotal`, `calcTotal` |
| JS/TS 类/组件/类型 | 大驼峰 | `InvoiceCard` |
| JS/TS 常量 | 全大写下划线 | `MAX_RETRY_COUNT` |
| Python 变量/函数 | 小写下划线 | `invoice_total` |
| Python 类 | 大驼峰 | `InvoiceParser` |
| Go | 驼峰，导出大写 | `CalcTotal` / `calcTotal` |
| 文件名 JS/TS | kebab-case 或与导出同名 | `invoice-card.tsx` |
| 文件名 Python | 小写下划线 | `invoice_parser.py` |
| CSS 类 | kebab-case 或 BEM | `nav-pill`, `card__title` |
| 环境变量 | 全大写下划线 | `DATABASE_URL` |

规则：同一概念全库一个词；缩写除非广为人知（URL/ID/API）否则展开；禁止单字母命名（循环变量 `i/j/k` 与数学域 `x/y` 除外）。

## 四、函数与控制流

- 卫语句提前返回，主路径不缩进在 else 里。
- 禁止布尔旗标参数：`render(true)` → 拆为 `renderPreview()` / `renderFinal()`。
- 纯函数优先，副作用集中在明确命名的函数（`syncXxx` / `saveXxx`）。
- 早绑定优于晚分支：能用数据表/映射替代 if-else 链 ≥4 分支时，用映射。

## 五、错误处理

- **快速失败**：非法输入在入口处拒绝，不带着坏数据往下走。
- 抛出**具体**错误：带类型/错误码与上下文（哪个参数、什么值、期望什么）。
- 禁止空 catch；确需忽略必须写明为什么（注释回答"为什么能安全忽略"）。
- 资源释放交给语言机制：`using`/`with`/`defer`/`finally`，禁止手工散落 close。
- 日志分级：error（需人处理）/ warn（可自动恢复）/ info（关键路径节点）/ debug（默认关闭）；每条日志带可定位上下文，禁止只打 "error occurred"。

## 六、注释规范（争议最终裁决）

### 6.1 允许且鼓励的三类

1. **为什么注释**：业务原因、绕坑说明、性能取舍、外部约束。
   ```js
   // 后端分页已限制单页 ≤1000，此处全量遍历是安全的
   ```
2. **契约注释**：公开 API 必注。写契约（入参域、返回值、异常、一个示例），不写实现过程。
   ```js
   /**
    * 计算发票含税总额。
    * @param {number[]} amounts - 不含税金额，均须 > 0
    * @param {number} taxRate - 税率，取值 [0, 1)
    * @returns {number} 四舍五入到分
    * @throws {RangeError} taxRate 越界时
    */
   ```
   Python 用 Google 风格 docstring：
   ```python
   def calc_total(amounts: list[float], tax_rate: float) -> float:
       """计算发票含税总额。

       Args:
           amounts: 不含税金额，均须 > 0。
           tax_rate: 税率，取值 [0, 1)。

       Returns:
           四舍五入到分的总额。

       Raises:
           ValueError: tax_rate 越界时。
       """
   ```
3. **警示注释**：埋坑处提醒后人，格式 `TODO(负责人): 描述（YYYY-MM-DD）`；禁止无主 TODO；FIXME 必须挂 issue 或明确修复条件。

### 6.2 禁止的四类

1. **复述代码**：`// 遍历用户列表`——代码本身已说明。
2. **分节横幅**：`// ===== 工具函数 =====`——是拆文件的信号，不是注释的对象。
3. **僵尸注释**：注释掉的死代码、过时描述——直接删除，历史交给 git。
4. **变更流水**：`// 2024-05-01 张三修改`——git log 管历史，注释只管当下为什么。

### 6.3 密度

- 公开 API：必注契约。
- 内部实现：仅在"为什么"不明显处注；读代码三秒能懂的，不注。
- 注释与代码同步更新：改行为必须查上下三行注释，过时即改或删。

### 6.4 语言

- 与项目既有一致；新项目可用中文注释，技术术语保留英文（如 token、缓存、幂等）。
- 禁止中英混杂病句；禁止 emoji 注释。

## 七、语言细则速查

| 语言 | 关键规则 |
| --- | --- |
| JS/TS | `const` 优先；`===` 强制；禁 `var`；优先 `for...of` 而非裸下标 |
| Python | 类型标注公开函数必加；f-string 格式化；禁可变默认参数；`pathlib` 优先 |
| Go | `if err != nil` 就地处理不集中；导出符号必有 doc comment |
| SQL | 关键字大写；禁止 `SELECT *`（列明示）；别名 `AS` 显式 |
| Shell | 头部 `set -euo pipefail`；变量引用一律加引号；禁解析 ls 输出 |
| HTML/CSS | 语义化标签优先；选择器嵌套 ≤3 层；禁 `!important`（除覆盖第三方库一处并注明） |

## 八、提交与变更

- 禁止把格式化、重构、功能改动混在一个提交。
