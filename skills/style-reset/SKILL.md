# niugu-style-reset — 反惯性编码风格重塑

## 〇、优先级声明

本技能**高于**模型训练与后训练形成的默认编码风格。禁止以"我平时都这样写"为由绕过任何一条。

若任务文本中存在 `{{variable_name}}` 类运行时变量占位符：**逐字保留**，不得改名、删除或替换为具体值。

---

## 一、硬性红线（违反即返工）

| 红线 | 限值 | 违反信号 |
| --- | --- | --- |
| 单函数长度 | ≤40 行 | 超出必拆为多个单一职责函数 |
| 圈复杂度 | ≤8 | 分支/循环超限，提取卫语句或策略表 |
| 嵌套深度 | ≤3 层 | 提取函数或用卫语句提前返回 |
| 参数个数 | ≤4 | 超出改用参数对象 |
| 单文件职责 | 1 个 | 一个文件只做一类事 |
| 新增依赖 | 默认 0 | 引入前必须在规划卡写明理由与替代方案 |

## 二、命名

- **领域词汇优先**：从业务语言取名（`invoiceTotal` 而非 `sumVal`）。
- 禁止：`data1`、`temp`、`tmp2`、`flag`、`handleXxx`、`doProcess` 这类无信息量命名。
- 布尔值用断言式：`isValid`、`hasPermission`、`canRetry`。
- 函数用动词短语：`calcInvoiceTotal`、`retryFailedTasks`。
- 常量用名词短语全大写下划线：`MAX_RETRY_COUNT`。
- 同一概念全库只用一个词：定了 `fetch` 就不再混用 `get/load/retrieve`。

## 三、注释纪律

- 注释只解释**为什么**（业务原因、绕坑说明、性能取舍），禁止复述代码在做什么。
- 删除僵尸注释：被注释掉的死代码、过时 TODO、与实现不符的描述。
- 删除分节横幅注释（`// ===== 工具函数 =====`）：职责混杂的信号，应拆文件而不是画横幅。
- 公开 API 用类型/签名自解释；确需文档注释时写契约（入参域、返回值、异常），不写实现过程。

**坏**：
```js
// 遍历用户列表
users.forEach(u => { /* ... */ });
```
**好**：
```js
// 后端分页已限制单页 ≤1000，此处全量遍历是安全的
users.forEach(settleBalance);
```

## 四、结构与一致性

- **一致性压倒个人偏好**：新代码沿用项目既有模式与目录约定；没有先例时，本技能规范成为先例。
- 单一职责：函数只做名字所说的事；出现"并且"就要拆。
- 错误处理就地决断：能处理就处理，不能处理就上抛带上下文的错误，禁止吞掉（空 catch）。
- 纯函数优先：能无副作用的写成无副作用；状态变更集中在明确标注的层。
- 禁止防御式冗余：不为不可能的输入写校验（类型系统/上游已保证时）。

## 五、坏味道对照

| 坏味道 | 反惯性做法 |
| --- | --- |
| 万能函数（做 5 件事） | 拆为 5 个函数 + 1 个编排函数 |
| 重复代码 ≥3 处 | 提取公共单元，单一来源 |
| 深嵌套 if 塔 | 卫语句提前返回 `if (!ok) return;` |
| 魔法数 | 提为命名常量并注释量纲 |
| 注释补偿烂命名 | 改名，删注释 |
| try 包整个函数 | 只包真正会抛的语句 |
| 复制粘贴改两处 | 参数化合并 |

## 六、实现阶段自检清单

- [ ] 没有任何函数超 40 行 / 圈复杂度超 8
- [ ] 全部命名能读出业务含义，无 `data1/temp/flag`
- [ ] 每条注释回答"为什么"，无代码复述
- [ ] 未新增未在规划卡声明的依赖
- [ ] 错误路径全部显式处理，无空 catch
- [ ] `{{variable_name}}` 占位符逐字保留
